# Snapbuild landing — Fullstack Developer test task

Расширенная реконструкция продуктового лендинга [Снэпбилд](https://snapbuild.ru/). Проект максимально близко воспроизводит структуру и визуальный язык исходной страницы и добавляет пять новых полноценных секций, логично продолжающих продуктовый рассказ.

> Статус: идёт повторный попиксельный аудит исходных секций, анимаций и адаптивов. Последняя production-сборка доступна в Docker, но проект не считается готовым до завершения визуальной сверки во встроенном браузере Codex. Публикация запускается вручную только после подтверждения пользователя.

## Опубликованная версия

[Целевой адрес после публикации: https://alkis12.github.io/snapbuild-fullstack-landing/](https://alkis12.github.io/snapbuild-fullstack-landing/)

До отдельного подтверждения workflow GitHub Pages не запускается. Проверяйте проект локально в Docker: `http://localhost:8080`.

## Локальный запуск

### Docker — основной способ проверки

```bash
docker compose up --build
```

После успешной сборки откройте [http://localhost:8080](http://localhost:8080). Остановка:

```bash
docker compose down
```

### Режим разработки

Требуется Node.js 22+.

```bash
npm install
npm run dev
```

Vite выведет локальный адрес, обычно `http://localhost:5173`.

### Проверка production-сборки

```bash
npm run build
npm run preview
```

## Стек

- React 19;

Закрытые ключи, API-токены и платные сервисы для запуска не требуются.

## Выполненные проверки

- `npm run lint` — без ошибок и предупреждений;
- `npm run build` — production-сборка Vite проходит;
- `npm audit` — 0 известных уязвимостей;
- `docker compose up -d --build` — контейнер Nginx собирается и отдаёт HTTP 200;
- встроенный браузер Codex — повторная визуальная проверка ожидает восстановления управляющего подключения; предыдущие скриншоты пользователя используются как дополнительные эталоны;
- логически и сборкой проверены переключатели контента и команд, автоматическая смена use-cases, мобильное меню, FAQ-мультиселект и оба состояния формы;
- проверены исходные тайминги движения: reveal `900 ms / 32 px`, направленная смена медиа `260 ms`, каскад мобильного меню и три анимированных слоя финального CTA;
- битые локальные ассеты сборкой не обнаружены; ошибки консоли и глобальный горизонтальный скролл требуется повторно подтвердить во встроенном браузере после восстановления подключения.

## Пять добавленных секций

1. **«Один продукт — для всей команды»** — интерактивные сценарии для маркетинга, дизайна, продаж и продукта без выдуманных метрик.
2. **«Одна идея — материалы для каждого канала»** — визуальная связка пяти продуктовых форматов на оригинальных интерфейсных медиа.
3. **«Дизайн-система становится рабочим инструментом»** — подключение языка бренда, компонентов и командного сценария.
4. **«Встраивается в существующую инфраструктуру»** — схема подтверждённых исходным FAQ интеграций и вариантов развертывания.
5. **«Покажем Снэпбилд на ваших материалах»** — демонстрационный сценарий и форма заявки с клиентской валидацией.

## Как анализировалась стилистика исходного сайта

Исходная страница изучалась на desktop-размере и в адаптивных состояниях. CSS живого лендинга был выгружен из подключённых таблиц стилей и сопоставлен с локальными селекторами по геометрии, типографике, переходам и keyframes. Зафиксированы повторяющиеся паттерны: TT Commons Pro, фон `#f5f5f6`, крупные заголовки с плотным интерлиньяжем, белые карточки со скруглением 16–24 px, чёрные CTA, тонкие разделители и фирменный градиент из персикового, розового и лавандового. Новые секции используют те же токены, типографическую иерархию, сетку, отступы и характер интерактивных состояний.

Оригинальные медиафайлы взяты с публичного лендинга в рамках разрешения тестового задания и хранятся локально в `public/assets` — проект не зависит от доступности внешнего сайта.

## Что удалось воспроизвести

- фиксированную стеклянную шапку и мобильное меню;
- градиентный первый экран с оригинальным продуктовым превью;
- логотипы клиентов;
- продуктовые карточки «Одна платформа — весь маркетинг»;
- интерактивный блок форматов контента со всеми 20 оригинальными медиа-состояниями, 8-секундным автопереключением и прогрессом;
- сравнительную таблицу;
- блок безопасности с оригинальными иллюстрациями;
- горизонтальный роадмап;
- FAQ-мультиселект с независимыми колонками;
- финальный градиентный CTA и структурированный подвал;
- адаптивные версии для 1280, 768 и 375 px.

## Что не удалось реализовать и почему

На текущем этапе критичных исключений нет. Форма заявки сознательно не отправляет данные на сервер: по ТЗ достаточно базовой клиентской валидации и понятного состояния успешной отправки. Все внешние продуктовые действия заменены безопасными переходами к локальной демо-форме.

## Что улучшить при наличии дополнительного времени

- добавить visual-regression тесты по эталонным скриншотам;
- настроить e2e-набор для всех интерактивных состояний;
- провести дополнительную оптимизацию изображений по форматам и размерам экрана;
- добавить полноценную локализацию и CMS для контента.

## Использованные AI-инструменты

- **OpenAI Codex** — анализ ТЗ, аудит исходного лендинга, архитектура, React/CSS-реализация, Docker/GitHub Pages-конфигурация, адаптивное и интерактивное тестирование;
- встроенный браузер Codex — визуальный анализ оригинала и тесты localhost на desktop/tablet/mobile;
