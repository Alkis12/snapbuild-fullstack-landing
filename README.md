# Snapbuild landing — Fullstack Developer test task

Расширенная реконструкция продуктового лендинга [Снэпбилд](https://snapbuild.ru/). Проект максимально близко воспроизводит структуру и визуальный язык исходной страницы и добавляет пять новых полноценных секций, логично продолжающих продуктовый рассказ.

> Статус: реализация и локальная browser-QA завершены. Проект готов к проверке в Docker; публикация запускается вручную после подтверждения.

## Опубликованная версия

[Целевой адрес после публикации: https://alkis12.github.io/snapbuild-fullstack-landing/](https://alkis12.github.io/snapbuild-fullstack-landing/)

До отдельного подтверждения workflow GitHub Pages не запускается. Проверяйте проект локально в Docker: `http://localhost:8080`.

## Локальный запуск

### Docker — основной способ проверки

```bash
docker compose up --build
```

После успешной сборки откройте [http://localhost:8080](http://localhost:8080). Остановка:

```bash
docker compose down
```

### Режим разработки

Требуется Node.js 22+.

```bash
npm install
npm run dev
```

Vite выведет локальный адрес, обычно `http://localhost:5173`.

### Проверка production-сборки

```bash
npm run build
npm run preview
```

## Стек

- React 19;
- Vite;
- чистый CSS с адаптивной сеткой и анимациями;
- семантический HTML и доступные ARIA-состояния;
- Docker multi-stage build: Node.js 22 → Nginx;
- GitHub Actions + GitHub Pages.

Закрытые ключи, API-токены и платные сервисы для запуска не требуются.

## Выполненные проверки

- `npm run lint` — без ошибок и предупреждений;
- `npm run build` — production-сборка Vite проходит;
- `npm audit` — 0 известных уязвимостей;
- `docker compose up -d --build` — контейнер Nginx собирается и отдаёт HTTP 200;
- встроенный браузер Codex — визуальная проверка desktop, tablet и mobile;
- проверены переключатели контента и команд, слайдер отзывов, тарифный toggle, FAQ и оба состояния формы;
- во всех проверенных состояниях отсутствуют ошибки/предупреждения консоли, битые изображения и глобальный горизонтальный скролл.

## Пять добавленных секций

1. **«Один продукт — разные команды»** — интерактивные сценарии для маркетинга, дизайна, продаж и продукта.
2. **«Бренд быстрее бизнеса больше не тормозит»** — продуктовые метрики и последовательность выпуска кампании.
3. **«От дизайн-системы до первого запуска»** — четыре этапа внедрения и корпоративные интеграции.
4. **«Команды замечают результат»** — управляемый слайдер отзывов с измеримыми результатами.
5. **«Начните с подходящего масштаба»** — тарифные форматы, переключатель периода и форма заявки с клиентской валидацией и состоянием успешной отправки.

## Как анализировалась стилистика исходного сайта

Исходная страница изучалась на desktop-размере и в адаптивных состояниях. Зафиксированы повторяющиеся паттерны: TT Commons Pro, фон `#f5f5f6`, крупные заголовки с плотным интерлиньяжем, белые карточки со скруглением 16–24 px, чёрные CTA, тонкие разделители и фирменный градиент из персикового, розового и лавандового. Новые секции используют те же токены, типографическую иерархию, сетку, отступы и характер интерактивных состояний.

Оригинальные медиафайлы взяты с публичного лендинга в рамках разрешения тестового задания и хранятся локально в `public/assets` — проект не зависит от доступности внешнего сайта.

## Что удалось воспроизвести

- фиксированную стеклянную шапку и мобильное меню;
- градиентный первый экран с оригинальным продуктовым превью;
- логотипы клиентов;

## Что не удалось реализовать и почему

На текущем этапе критичных исключений нет. Форма заявки сознательно не отправляет данные на сервер: по ТЗ достаточно базовой клиентской валидации и понятного состояния успешной отправки. Все внешние продуктовые действия заменены безопасными переходами к локальной демо-форме.
